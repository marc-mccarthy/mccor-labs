# Infra review — 2026-10-04

Scope: `infra/` (Terraform + `infra/deploy.sh`) against what the static export in `app/web` needs.
This was review only: no file in `infra/` or `app/` was changed. Static checks ran on scratch copies.

## Summary

The delivery path is sound. Every route, payload and media type the export needs is served
correctly, and the core controls (OAC, scoped bucket policy, TLS and errors) are right.

The real risk is credentials, not the website:

- Live mail and SES secrets sit in a world-readable local state backup and in remote state.
- Those secrets are reachable by a long-lived, likely-admin static IAM key that is also used for
  routine publishing.

Two problems apply to the site directly:

- The CloudFront distribution sends no security headers at all.
- The owner's uncommitted 1Password rename blocks every `deploy.sh` action, including `publish`.

Counts: 5 HIGH, 5 MEDIUM, 12 LOW, 3 INFO.

Static checks, run on copies:

- `terraform fmt -check -recursive`: rc 0.
- `terraform init -backend=false` and `validate`: rc 0 for the root and for `setup/`. The root
  warns about 2 undeclared variables.
- `shellcheck deploy.sh`: rc 0.
- tflint 0.64.0: 9 unused declarations in the root, plus a missing `required_version` in each of
  `static_site` and `certificate`.
- trivy 0.74.0: 5 findings in `static_site`, no CRITICAL.
- checkov: not installed.

## What the website needs from infra (expert D)

- [x] Root-absolute paths, with no base path: `/_next/static/…`, `/media/…`, `/fonts/…`.
- [x] Trailing-slash routes resolve to `<dir>/index.html`: `/`, `/services/`, `/process/`,
      `/about/`, `/contact/`, `/careers/`, `/privacy/`, `/terms/`, `/work/`.
- [ ] No-slash routes should 301 to the slash form. Today they get a 200 rewrite (F12).
- [x] Unknown paths get `/404.html` with status 404.
- [ ] `/404/` and `/_not-found/` must not answer 200 (F13).
- [x] RSC `*.txt` is served with `?_rsc=` ignored, as `text/plain`, which the client accepts (F25).
- [x] `/opengraph-image.jpg?…` and `/twitter-image.jpg?…` are served as `image/jpeg`, with the
      query string ignored.
- [x] `robots.txt` and `sitemap.xml` are served at the root. `/work/` is missing from the sitemap;
      that is an app issue, out of scope here.
- [x] `.woff2` is served as `font/woff2`, same origin, and preloaded with `crossorigin`.
- [x] `.mp4` and `.webm` are served with Range support.
- [ ] `.mp4` and `.webm` need a sensible cache lifetime (F15).
- [x] `.json` and `.glsl` can be fetched same-origin from `/media/brand/`.
- [x] `/_next/static/**` is cached immutable for 1 year.
- [x] HTML and `.txt` revalidate.
- [ ] Old chunks must stay available for open tabs (F22).
- [ ] A CSP is needed (F4). It must allow inline scripts and styles, same-origin `connect-src`,
      `media-src`, `font-src` and `img-src`. No eval, wasm, workers or frames are needed.
- [x] Canonical host is the apex `mccorlabs.com`.
- [x] `www` redirects to the apex.
- [ ] `*.cloudfront.net` should also redirect to the apex (F11).
- [ ] Only approved files may reach the bucket (F7).

## Recommended fix order

1. **F5.** One-line class fix (item ID in the template). It unblocks every later step, and nothing
   else can be applied or published until it lands.
2. **F6 → F1.** Remove xtrace from the user data first. Then rotate the SES key and the mailbox
   passwords, and `chmod 600` or delete the local backups (owner's call).
3. **F2 + F3.** Short-lived credentials, a scoped publish role, a state-bucket policy denying
   `setup/*`, a TLS deny, and deactivating the stale `~/.aws/credentials` key.
4. **F4.** Response headers policy, with the CSP shipped Report-Only first. Ship it with F11, F12
   and F14 in the same function/distribution change.
5. **F7 + F13 + F22 + F15.** One `deploy.sh` pass: pre-sync guard, 404 excludes, no `--delete` on
   chunks, media cache class.
6. Remaining LOWs (F8 after reviewing DMARC reports; F16–F21, F23–F24) as housekeeping.
